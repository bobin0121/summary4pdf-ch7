# PRD: PDF 요약 웹 앱

단계: 0단계(PRD). 이 문서는 무엇을 만들지만 정한다. 설계와 코드는 다음 단계에서 다룬다.

표기: 사용자가 정한 내용은 그대로 옮겼다. 사용자가 정하지 않아 PM이 둔 값은 "가정"으로, 아직 정하지 못한 것은 "결정 필요"로 표시했다.

## 1. 제품 목표

대학생이 강의 자료나 논문 PDF를 올리면, AI가 핵심 내용을 한국어로 요약해 보여 준다. 학생은 긴 문서를 다 읽기 전에 핵심을 빨리 파악하고, 시험 공부나 과제 준비에 쓴다.

제약: 비용은 0원이다. AI 모델은 OpenRouter의 무료 모델(이름이 `:free`로 끝나는 모델)만 쓴다.

## 2. 대상 사용자

- 대학생. 강의 자료(슬라이드를 내보낸 PDF 등)나 논문 PDF를 자주 받는다.
- 원문이 영어인 경우가 많고, 한국어로 먼저 훑어보고 싶어 한다.
- 회원가입이나 설정 없이 바로 쓰기를 원한다.

## 3. 사용자 스토리

- U1. 대학생으로서, PDF를 화면에 끌어다 놓아 올리고 싶다. 파일 찾는 시간을 줄이기 위해서다.
- U2. 대학생으로서, 파일 선택 창으로도 올리고 싶다. 끌어다 놓기가 불편한 기기에서도 쓰기 위해서다.
- U3. 대학생으로서, 문서의 한 줄 요약을 보고 싶다. 이 자료가 무엇에 관한 것인지 바로 알기 위해서다.
- U4. 대학생으로서, 핵심 개념 3~5개를 보고 싶다. 시험 범위에서 무엇을 외워야 하는지 잡기 위해서다.
- U5. 대학생으로서, 중요한 정의나 공식을 따로 보고 싶다. 과제와 시험에 그대로 쓰기 위해서다.
- U6. 대학생으로서, 영어 논문도 한국어 요약으로 읽고 싶다. 읽는 부담을 줄이기 위해서다.
- U7. 대학생으로서, 실패했을 때 무엇이 문제인지 알고 싶다. 파일을 고치거나 다시 시도할지 판단하기 위해서다.

## 4. 사용자 시나리오

### 4.1 정상: 한국어 PDF 요약
1. 사용자가 앱에 들어온다. 업로드 화면이 보인다.
2. 한국어 강의 자료 PDF를 업로드 영역에 끌어다 놓는다.
3. 앱이 파일을 확인한 뒤 진행 화면으로 바뀐다. "요약하는 중" 문구가 보인다.
4. 요약이 끝나면 결과 화면이 나온다. 한 줄 요약, 핵심 개념 3~5개, 중요한 정의나 공식이 보인다.
5. 사용자가 "다른 PDF 올리기"를 눌러 업로드 화면으로 돌아간다.

### 4.2 영어 PDF
1. 사용자가 영어 논문 PDF를 올린다(누르면 열리는 파일 선택 창으로 골라도 된다).
2. 진행 화면을 거쳐 결과 화면이 나온다.
3. 요약 전체가 한국어다. 영어 전문 용어는 한국어 뒤에 괄호로 원어를 병기할 수 있다(예: 과적합(overfitting)). 수식과 기호는 원문 그대로 둔다.

### 4.3 너무 큰 파일
1. 사용자가 한도(가정: 4MB)를 넘는 PDF를 올린다.
2. 앱은 AI를 부르기 전에 막고, 오류 안내를 보여 준다. 업로드 화면에서 다시 고를 수 있다.

### 4.4 PDF가 아닌 파일
1. 사용자가 이미지, 워드 파일 등 PDF가 아닌 파일을 올린다.
2. 앱은 AI를 부르기 전에 막고, PDF만 올릴 수 있다고 안내한다.
3. 확장자만 `.pdf`로 바꾼 파일도 PDF로 열리지 않으면 같은 방식으로 안내한다.

### 4.5 글자가 없는 PDF(스캔본)
1. 사용자가 사진을 찍어 만든 스캔 PDF를 올린다. 글자를 읽어 낼 수 없다.
2. 글자 인식(OCR)은 이번 범위 밖이므로, 앱은 글자가 없는 PDF라고 안내한다. 글자를 복사할 수 있는 PDF를 올리도록 알려 준다.
3. 이 경우 AI를 부르지 않는다. 무료 호출을 아끼기 위해서다.

### 4.6 AI 실패
1. 정상 PDF를 올렸지만 AI 호출이 실패한다. 원인은 시간 초과, 무료 호출 한도(429), 모델 목록에서 빠짐(404), 빈 응답, 형식 오류 등이다.
2. 앱은 다음 무료 모델로 넘어가 다시 시도한다. 모든 모델이 실패하면 원인을 알 수 있는 오류 안내를 보여 준다.
3. 사용자는 "다시 시도"로 같은 파일을 다시 요약하거나, 다른 파일을 올릴 수 있다.

## 5. 화면 명세

화면은 한 페이지 안에서 상태가 바뀌는 방식으로 한다(가정). 상태는 업로드, 진행, 결과, 오류 네 가지다. 완결된 문장은 마침표로 끝내고, 버튼 라벨과 제목은 마침표를 붙이지 않는다.

### 5.1 업로드 상태
보이는 요소:
- 제목: "PDF 요약"
- 한 줄 설명: "강의 자료나 논문 PDF를 올리면 핵심 내용을 한국어로 요약해 드립니다."
- 업로드 영역(점선 상자): 안내 문구 "PDF 파일을 여기로 끌어다 놓으세요."와 보조 문구 "또는 눌러서 파일을 선택하세요."
- 제한 안내: "PDF만 올릴 수 있고, 크기는 4MB까지입니다. 글자를 복사할 수 있는 PDF만 요약됩니다."
- 업로드 영역을 누르면 파일 선택 창이 열리고, 선택 창은 PDF만 보이게 한다.

상태별 모양:
- 기본: 점선 상자.
- 파일을 끌고 영역 위에 올렸을 때: 상자 테두리와 배경이 강조되고 문구가 "놓으면 올라갑니다."로 바뀐다.
- 키보드: 업로드 영역에 포커스가 가고, Enter나 Space로 파일 선택 창이 열린다.
- 빈 상태: 이 화면 자체가 처음 상태다. 별도 목록은 없다.

### 5.2 진행 상태
- 파일 이름과 크기를 보여 준다.
- 진행 표시(돌아가는 표시)와 문구: "요약하는 중입니다. 문서 길이와 서버 상황에 따라 시간이 걸릴 수 있습니다."
- 시간을 보장하지 않는다는 뜻으로, 몇 초 걸린다는 약속 문구는 쓰지 않는다.
- 진행 중에는 새 파일을 올릴 수 없다. "취소" 버튼으로 요청을 멈추고 업로드 상태로 돌아갈 수 있다.
- 오래 걸릴 때(가정: 30초 넘으면) 보조 문구를 추가한다: "무료 AI 모델을 쓰고 있어 평소보다 오래 걸릴 수 있습니다. 조금만 기다려 주세요."

### 5.3 결과 상태
보이는 요소(위에서 아래 순서):
- 파일 이름
- "한 줄 요약": 한 문장.
- "핵심 개념": 3~5개. 각 항목은 개념 이름과 짧은 설명으로 이루어진다.
- "중요한 정의와 공식": 항목마다 이름과 내용을 적는다. 수식은 텍스트로 읽을 수 있게 보여 준다.
- 버튼: "다른 PDF 올리기"
- 하단 안내(작은 글씨): "AI가 만든 요약이므로 중요한 내용은 원문과 함께 확인하세요."

빈 상태 처리:
- 문서에 정의나 공식이 없으면 "중요한 정의와 공식" 영역에 "이 문서에서 뚜렷한 정의나 공식을 찾지 못했습니다."를 보여 준다. 영역을 숨기지 않는다.
- 핵심 개념이 3개 미만으로 나오는 아주 짧은 문서는 나온 만큼만 보여 준다(결정 필요 7번 참고).

### 5.4 오류 상태
공통 모양: 오류 제목, 원인 설명, 할 일 안내, 버튼. 오류가 나도 앱은 멈추지 않고 업로드로 돌아갈 수 있다.

| 상황 | 제목 | 문구 | 버튼 |
|---|---|---|---|
| PDF가 아님 | 올릴 수 없는 파일입니다 | PDF 파일만 올릴 수 있습니다. 파일 형식을 확인한 뒤 다시 올려 주세요. | 다시 올리기 |
| 파일이 너무 큼 | 파일이 너무 큽니다 | 4MB 이하의 PDF만 올릴 수 있습니다. 필요한 쪽만 나눠서 올려 주세요. | 다시 올리기 |
| 열 수 없는 PDF(깨짐, 암호) | PDF를 열 수 없습니다 | 파일이 손상되었거나 암호가 걸려 있을 수 있습니다. 다른 파일로 시도해 주세요. | 다시 올리기 |
| 글자가 없는 PDF | 글자를 찾을 수 없습니다 | 스캔한 이미지로 된 PDF는 지원하지 않습니다. 글자를 복사할 수 있는 PDF를 올려 주세요. | 다시 올리기 |
| AI 시간 초과 | 요약이 너무 오래 걸립니다 | AI 응답이 제때 오지 않았습니다. 잠시 뒤 다시 시도해 주세요. | 다시 시도 |
| AI 호출 한도 | 오늘 쓸 수 있는 요약 횟수를 넘었습니다 | 무료 AI 모델의 호출 한도에 도달했습니다. 나중에 다시 시도해 주세요. | 다시 시도 |
| AI 전체 실패(빈 응답, 형식 오류, 모델 없음 등) | 요약하지 못했습니다 | AI가 올바른 요약을 만들지 못했습니다. 다시 시도하거나 다른 파일로 해 보세요. | 다시 시도 |
| 네트워크 끊김 | 연결에 실패했습니다 | 인터넷 연결을 확인한 뒤 다시 시도해 주세요. | 다시 시도 |

오류 문구에는 서버 내부 정보, 키, 모델 응답 원문을 넣지 않는다.

## 6. 기능 요구 사항

| 번호 | 요구 사항 | 받아들임 기준 |
|---|---|---|
| F1 | 끌어다 놓기 업로드 | PDF 파일을 업로드 영역에 끌어다 놓으면 업로드가 시작된다. 끌고 올라간 동안 영역이 강조된다. 영역 밖에 놓아도 브라우저가 파일을 열어 버리지 않는다. |
| F2 | 눌러서 파일 선택 | 업로드 영역을 누르면 파일 선택 창이 열리고 PDF를 고를 수 있다. 키보드(Enter, Space)로도 열린다. |
| F3 | 파일 형식 검사 | PDF가 아닌 파일은 AI를 부르기 전에 막고 5.4의 "올릴 수 없는 파일입니다"를 보여 준다. 확장자와 파일 내용을 모두 확인한다. |
| F4 | 파일 크기 제한 | 4MB(가정)를 넘는 파일은 AI를 부르기 전에 막고 "파일이 너무 큽니다"를 보여 준다. 한도는 Vercel 요청 본문 한도 4.5MB보다 작다. |
| F5 | PDF 글자 추출 | 글자를 복사할 수 있는 PDF에서 본문 글자를 뽑아낸다. 한국어와 영어 문서 모두 시험한다. |
| F6 | 글자 없음 처리 | 뽑은 글자가 없거나 지나치게 적으면(기준은 결정 필요 3번) AI를 부르지 않고 "글자를 찾을 수 없습니다"를 보여 준다. |
| F7 | 한국어 요약 생성 | OpenRouter 무료 모델이 문서 내용으로 한 줄 요약, 핵심 개념 3~5개, 중요한 정의나 공식을 만든다. 원문이 영어여도 요약은 한국어다. |
| F8 | 결과 화면 | 한 줄 요약, 핵심 개념, 중요한 정의와 공식이 5.3의 순서로 화면에 나온다. 정의나 공식이 없으면 안내 문구가 나온다. |
| F9 | 진행 표시 | 요약하는 동안 진행 상태가 보이고, 취소할 수 있다. 시간을 약속하는 문구는 없다. |
| F10 | 모델 대체 | 첫 모델이 실패하면(시간 초과, HTTP 오류, 빈 응답, 형식 오류) 다음 무료 모델로 넘어간다. 모두 실패하면 F11의 안내를 보여 준다. 유료 모델은 어떤 경우에도 부르지 않는다. |
| F11 | 이해할 수 있는 오류 안내 | 5.4의 상황마다 원인과 할 일이 적힌 안내가 나온다. 안내는 항상 한국어이고, 내부 오류 문구와 키는 노출되지 않는다. 오류 뒤에 업로드 상태로 돌아갈 수 있다. |
| F12 | 전체 시간 제한 | AI 호출 전체에 경과 시간 기준 시간 제한을 둔다. 배포 함수 시간 한도(`maxDuration`)보다 짧다(구체 값은 설계에서 정한다). 제한을 넘으면 "요약이 너무 오래 걸립니다"를 보여 준다. |
| F13 | 키 보호 | AI 키는 환경 변수 `OPENROUTER_API_KEY`로만 서버에서 읽는다. 브라우저로 보내지 않고, 공개 변수에 넣지 않는다. |
| F14 | 파일 비저장 | 올린 PDF와 요약은 서버에 저장하지 않는다(가정). 요청을 처리하고 나면 버린다. 화면 안내에 "올린 파일은 저장되지 않습니다."를 넣는다. |

## 7. 범위 밖(이번에 만들지 않는다)

사용자가 뺀 기능:
- 회원가입과 로그인
- 문서에 질문하기(채팅)
- 스캔 PDF 글자 인식(OCR)
- 여러 PDF 한꺼번에 올리기

PM이 함께 범위 밖으로 둔 것(결정 필요가 아니라, 사용자가 정한 범위에서 추측으로 넓히지 않기 위한 것):
- 요약 기록 저장, 다시 보기
- 요약 내려받기, 복사 버튼, 공유
- 요약 길이나 문체 설정
- 한국어 외 다른 언어로 요약
- 사용량이나 방문 통계 수집

## 8. 완료 기준

사용자가 정한 완료 기준:
1. 한국어 요약이 화면에 나온다. 영어 PDF에서도 요약이 한국어로 나온다.
2. 실패하면 이해할 수 있는 오류 안내가 나온다.

위 두 기준을 확인하는 방법(받아들임 기준과 연결):
- 한국어 PDF 1개, 영어 PDF 1개를 실제로 올려 결과 화면의 세 영역이 모두 나오는지 본다(F5, F7, F8). 무료 호출이 하루 약 50회이므로 실제 호출 시험은 최소한으로 한다.
- 오류 시나리오 4.3, 4.4, 4.5는 AI를 부르지 않고 확인한다(F3, F4, F6). 4.6은 AI 호출을 막거나 가짜 응답으로 확인한다(F10, F11).
- 모든 오류 문구에 원인과 할 일이 들어 있고, 키나 내부 오류 문구가 보이지 않는다(F11, F13).
- 코드 단계에서는 프로젝트 규칙대로 `npm test`, `npm run lint`, `npm run build`를 통과하고, 배포한 주소에서 실제 PDF로 한 번 요약해 본 뒤에 완료로 본다.

## 9. 비용과 환경 원칙

- 비용 0원: OpenRouter 무료 모델(`:free`)만 쓴다.
- 환경 변수는 이름만 적는다: `OPENROUTER_API_KEY`. `.env`는 열지 않고 커밋하지 않는다.
- 배포 환경(Vercel) 제약: 함수가 받는 요청 본문은 4.5MB까지이므로 업로드 한도는 그보다 작게 둔다.

## 10. 열린 질문(설계 단계에서 정할 것)

1. 올릴 수 있는 PDF 크기. 가정은 4MB다. Vercel 요청 본문 한도(4.5MB)에서 여유를 둔 값이다. 요청 본문에 파일 외 정보가 더해지는 방식(예: 인코딩으로 커지는 경우)이 정해지면 값을 다시 확인한다. 4MB가 넘는 자료를 많이 쓰는지는 사용자가 알려 줘야 한다.
2. 요약을 기다리는 시간. 정하지 않았다. 무료 모델이라 시간을 보장하지 않는다. 설계에서 전체 시간 제한과 "오래 걸린다" 안내를 띄울 시점(가정은 30초)을 정한다.
3. 글자 없음의 기준. 뽑힌 글자가 몇 자 미만이면 "글자 없음"으로 볼지 정한다.
4. 긴 문서 처리. 무료 모델의 입력 길이 한계를 넘는 긴 PDF(예: 수백 쪽)는 앞부분만 쓸지, 나눠 요약할지, 쪽 수를 제한할지 정한다. 나눠 요약하면 호출 횟수가 늘어 하루 약 50회 한도를 더 빨리 쓴다.
5. 사용할 무료 모델 목록과 순서. 목록에서 빠지거나(404) 몰릴 수(429) 있으므로 설계 시점에 확인한다.
6. 요약 결과의 형식. AI가 일정한 구조(한 줄 요약, 개념 목록, 정의 목록)로 답하게 하고 어긋나면 어떻게 처리할지(다음 모델로 넘김 또는 재시도) 정한다.
7. 핵심 개념이 3개 미만이거나 5개를 넘을 때의 처리. 문서가 매우 짧을 때 3개 미만을 허용할지 정한다.
8. 공식 표시 방법. 수식을 일반 글자로 보여 줄지, 수식 표현 도구를 쓸지 정한다. 우선은 글자 표시를 가정한다.
9. 호출 한도(429) 때문에 실패하는 일을 줄이기 위한 방법이 필요한지(예: 같은 사람의 연속 요청 제한). 로그인을 두지 않으므로 방법을 정한다면 설계에서 정한다.
10. 모바일 화면에서 끌어다 놓기가 어려우므로, 모바일은 눌러서 선택만 되어도 되는지 확인한다.
11. 파일 비저장(F14)과 요약 전 개인정보 안내 문구를 어디까지 넣을지(가정은 업로드 상태에 한 줄).
